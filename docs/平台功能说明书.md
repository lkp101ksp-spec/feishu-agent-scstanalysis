# 飞书科研 Agent 平台 — 功能说明书

> 版本：2026-09-04（Phase 29 收官版） · 测试基线 987 用例全绿
> 面向读者：平台使用者（飞书内交互）与管理员（部署/扩展）

---

## 1. 平台概述

一个部署在本机的飞书机器人后台，把「聊天助手、文档协作、生信分析、编码代理」四类能力聚合进同一个会话。你在飞书里发消息或指令，后台编排 LLM、Docker 沙箱与本地工具完成任务，结果回到 IM 与飞书文档。

```
飞书 IM（单聊/群聊）
   │  长连接（ws_client，单实例守卫）
   ▼
gateway（验签/限流/幂等 → 路由）
   ▼
orchestrator（研究链路 / code 链路 / 模板评论）
   ├── LLM Router（主模型 + fallback）
   ├── 工具面：code 六原语 · skill 工具 · sc_*/st_* 容器工具
   └── 审批卡 + PostgreSQL 审计
```

**三种使用形态：**

| 形态 | 入口 | 适合 |
|---|---|---|
| 即问即答 | 直接发消息 | 快速问答，答案可写回绑定文档 |
| 研究任务 | `/research <描述>` | 多步规划执行（DAG），生成分析+图+文档写回 |
| 编码代理 | `/code <描述>` | 在会话工作区写代码、跑脚本、调 skill 干活 |

## 2. 对话与文档协作

### 2.1 绑定文档（bind-doc）

```
/bind-doc <doc_id 或文档链接 或 wiki 链接> [@章节锚点]
/bind-doc-renew
```

- 支持裸 doc_id、`/docx/` 分享链接、`/wiki/` 知识库链接三种形态
- 绑定即探活（文档不存在立即报错，防一字之差错绑）
- 有效期默认 30 分钟；剩余 ≤5 分钟自动弹「续期」卡片；也可手动 `/bind-doc-renew`
- 指定锚点后，写入内容统一插到该章节下方

### 2.2 写回三种方式

| 方式 | 触发 | 行为 |
|---|---|---|
| 自动写回 | 绑定文档后普通对话 | 每条回复先发 IM，再追加写入绑定文档 |
| 定点写入 | `#写到 <章节标题> \| <内容>` | 消息级临时锚点，只写这一次 |
| 研究写回 | `/research` 完成后 | 发「同意写入 / 跳过」审批卡，点击后写入（默认 `card_confirm` 模式） |

### 2.3 模板与评论（12 条指令）

`/template-list` `/template-find <关键词> [#标签]` `/template-fork <id>` `/template-share <id>` `/template-tag <id> <tag>` `/template-favorite <id>` `/template-favorites` `/template-diff <id> <vA> <vB>` `/template-rollback <id> <ver>` `/template-submit-public <id>` `/comments <doc_id> [block_id]` `/comments-sync <doc_id>` `/comment-apply <doc_id>`

模板支持版本/收藏/公共审核/fork；评论支持拉取同步与「指令评论」批量应用（如评论里写 `#fix` 由 agent 执行）。

> 群聊内仅响应指令（`/` 开头或 `#写到`），闲聊静默；私聊全功能。

## 3. /research 研究任务

```
/research 总结当前绑定文档的核心内容并给出三条研究建议
```

受理即回，后台执行：

1. 注入绑定文档上下文（过期则提示重新绑定）
2. **Planner 规划 DAG**（可见 L0/L1 工具，write_doc 节点需审批）
3. **Scheduler 并发执行**（含 sc_*/st_* 节点时墙钟放宽至 1h）
4. 结果写回文档 + IM 摘要（节点状态/失败详情/关键输出）
5. 分析图（umap/dotplot/spatial）逐张发到 IM 并追加文档

失败自愈：run_python 节点代码级失败由 LLM 自动修复重试 1 次。

## 4. /code 编码代理

```
/code 写一个快速排序并自测
/code 用 qc_stat_run 对 processed.h5ad 做质控统计
/code clear        ← 清空会话工作区
```

### 4.1 工作方式

每个聊天有独立持久工作区 `code_workspace/code_<hash>/`（跨任务保留，`clear` 才清空）。Agent 多轮「思考→调工具→观察」直至完成：

- **六原语**：`read_file` `write_file` `edit_file` `list_dir` `search_files` `run_cmd`——文件操作全部锁在工作区内（路径逃逸直接拒绝）
- **run_cmd 三态**：白名单直跑（python/pytest/git 只读等）→ 其余发审批卡 → 危险命令直接拒（format/shutdown/rd /s 等）
- **生信工具面**：`sc_*` 系列可直接调用（默认白名单，`code_registry_tools` 可调）
- **skill 工具面**：见下节
- 三重保险：25 步 / 200k tokens / 1h 超时；上下文临界自动压缩历史

### 4.2 过程反馈与结果

- 每 3 个工具事件推一行进度：`[进行中] step 4 · ✓list_dir ✗run_cmd`
- 完成回复：`[coding 完成] 步数 6 · 工具 2✓/0✗ · ~908 tokens` + 中文总结（做了什么/关键结果/产物路径）

### 4.3 Working Memory（工作记忆）

任务内滚动记忆消息，模型每轮可见：

- **失败段**（≤5 行）：已失败的调用与真实报错——避免重复相同的失败尝试
- **成功段**（≤3 行）：已成功的调用与产出摘要——跨步复用结果（如大文件读过的统计数直接引用，不重跑）

### 4.4 连败保护

工具连续 3 步失败 → 自动禁用工具，引导模型文字总结现状（防无限烧钱重试）；此时任务判定为实质失败，自动触发 skill 诊断（见 5.3）。

## 5. skill 系统（可扩展工具包）

### 5.1 结构与热加载

```
skills/<name>/
├── SKILL.md     # frontmatter(name+description) + 使用知识正文
└── tools.yaml   # 可选：CLI 工具定义
```

- **热加载**：每次 /code 任务自动扫描，新增 skill 目录即时生效，无需重启
- **语义检索**：任务下发时由 LLM 从 skill 候选清单中按语义挑选相关的注入提示（中文任务可命中英文 skill，反之亦然）；LLM 不可用时回退词元匹配
- 每个工具默认 L2（调用前发审批卡）

### 5.2 tools.yaml 工具定义

```yaml
tools:
  - name: my_tool
    description: 一句话功能
    parameters:
      type: object
      properties:
        input_path: {type: string}
      required: [input_path]
    command: ["I:/飞书agent/.venv/Scripts/python.exe", "run.py"]  # 参数自动 --k v 展开
    timeout_sec: 600
    image: bio:cpu-latest        # 可选：容器隔离执行
```

**容器隔离**（配 `image` 即启用）：`docker run --rm --network none --cpus 2 --memory 4g -v <skill目录>:/skill:ro`——断网、限额、只读挂载；不配 `image` 则本机直跑。注意：容器内 skill 目录只读，需写宿主产物的 skill 暂不适用容器模式。

### 5.3 失败诊断与半自动进化（Phase 27-28）

skill 工具失败导致任务失败时：

1. **诊断器**分析失败轨迹（含每次调用的真实 stderr、工具现有定义）→ 生成改进建议
2. 发出 **skill 改进审批卡**（问题 / 建议 / 目标文件 / patch 预览）
3. 你点「批准写回」→ 自动备份原文件为 `.bak` → 写回 SKILL.md（追加改进段落）或 tools.yaml（字段合并，schema 白名单过滤，幻觉字段自动丢弃）
4. 下次调用即生效——**skill 越用越准**

诊断纪律：issue 必须逐字引用真实报错、多个失败逐个归因（防「泛泛归因为超时」）；patch 参数名必须与现有工具定义一致（防盲猜）。

## 6. 生信分析工具（Docker 沙箱）

> 需管理员配置 `BIO_DATA_ROOTS` 数据白名单后才启用

### 6.1 单细胞 sc_*（5 工具）

| 工具 | 功能 | 产物 |
|---|---|---|
| `sc_load` | 读入 .h5ad 或 10x mtx 目录 | dataset_ref + 概要 |
| `sc_qc` | 质控过滤（min_genes/min_cells/max_mt_pct） | filtered.h5ad + 前后统计 |
| `sc_process` | 归一化→HVG→PCA→UMAP→Leiden | processed.h5ad + umap.png |
| `sc_markers` | 每簇差异基因 | markers JSON + dotplot.png |
| `sc_enrichment` | 富集分析（ORA 超几何 + GSEA prerank；hallmark/GO BP/KEGG 三基因集，镜像内离线） | 通路表 csv + 柱状图 png |
| `sc_plot` | 基因 violin / UMAP 着色（≤6 基因） | png 列表 |

### 6.2 空间转录组 st_*（8 工具）

`st_load` `st_qc` `st_process`（空间域聚类）`st_markers` `st_plot` `st_domains`（邻域细分+ARI）`st_commot`（配体受体通讯，CellChat 库+最优传输）`st_deconvolve`（cell2location 反卷积，可用 sc 产物作参考）

### 6.3 通用约定

- **dataset_ref**：12 位幂等键（同路径同大小数据自动复用工作区，文件变了视为新数据集）
- **沙箱**：断网容器 + CPU/内存限额；数据白名单目录只读挂载
- **磁盘治理**：中间产物 TTL 7 天、总量 10GB LRU 驱逐、2h 宽限保护进行中任务
- GPU：`bio_use_gpu=True` 时 sc_process/sc_markers 走 GPU 镜像

## 7. 安全与审批体系

| 层 | 机制 |
|---|---|
| 网关 | 签名校验、按 app 限流（60/min）、事件幂等去重（飞书重投不重复执行） |
| 工具分级 | L1 直接执行；L2（skill 工具、写文档、危险命令）必须审批卡放行 |
| 审批卡 | 仅任务发起者可点击（群聊他人点无效）；10 分钟超时按拒绝；重复点击幂等 |
| 沙箱 | 断网容器 + 资源限额 + 路径白名单；工作区路径逃逸拒绝 |
| 命令三态 | 白名单直跑 / 审批 / 危险命令硬拒 |
| 审计 | 所有卡片点击、skill 写回结果落 PostgreSQL `audit_logs`（可按 target_id 检索完整链） |
| 单实例 | pidfile 守卫，防双 ws_client 重复消费 |

## 8. 管理员速览

**启动**：`scripts\setup.ps1`（一键部署/幂等重装）→ `scripts\start.ps1`（一键启动：预检 + `--force` 后台拉起 + 日志确认）

**模型切换（Phase 30，可视化）**：管理员在飞书发 `/model` → 状态卡显示当前主备模型与候选池 → 点按钮**热切换（无需重启）**，DB 持久化（重启保持）。admin 名单 = `FEISHU_ADMIN_OPEN_IDS`；候选池 = `config/llm.yaml providers` 段（api key 只在 .env，不落库不回显）；切换全量审计（`llm_model_switched`/`_denied`）。

**关键配置**（`config/settings.py` / 环境变量）：

| 配置 | 默认 | 说明 |
|---|---|---|
| `FEISHU_ADMIN_OPEN_IDS` | 空 | 管理员名单（模板审核 + /model 切换共用；空=无人可切） |
| `BIO_DATA_ROOTS` | 空 | 数据白名单（逗号分隔），空则生信工具不注册 |
| `code_skills_dir` | `./skills` | skill 目录 |
| `code_registry_tools` | `sc_*` | /code 可调的 registry 工具前缀 |
| `code_max_steps` / `code_token_budget` / `code_timeout_sec` | 25 / 200000 / 3600 | AgentLoop 三上限 |
| `bio_use_gpu` | False | GPU 镜像开关 |
| `disabled_tools` | 空 | 全局工具禁用名单 |
| `research_writeback_approval` | card_confirm | 研究写回模式（card_confirm / bind_scope） |

**目录**：`code_workspace/`（/code 会话工作区，手动 clear）、`bio_workspace/`（生信产物，自动 GC）、`skills/`（skill 包）、`sandbox/`（生信容器脚本源码）

**镜像**：`feishu-research-agent/bio:cpu-latest` / `bio:st-cpu-latest` / `bio:gpu-latest`

## 9. 命令速查表

```
对话/文档
  /bind-doc <doc_id|链接> [@锚点]   绑定文档（30 分钟有效，自动续期卡）
  /bind-doc-renew                   手动续期
  #写到 <章节> | <内容>             定点写入（单次）

任务
  /research <描述>                  多步研究任务（DAG 规划执行）
  /code <描述>                      编码代理（工作区内干活）
  /code clear                       清空会话工作区

管理（仅 FEISHU_ADMIN_OPEN_IDS 名单）
  /model                            模型切换状态卡（按钮热切换主备）

模板/评论
  /template-list|find|fork|share|tag|favorite|favorites
  /template-diff|rollback|submit-public
  /comments <doc_id> · /comments-sync <doc_id> · /comment-apply <doc_id>
```

**常见问题**

- *审批卡点了没反应？* 重复点击幂等（首次已生效）；确认是任务发起者本人在点
- */code 说文件不存在？* 工作区是每聊天独立的，产物在 `code_workspace/code_<hash>/`；用 `/code 列出工作区文件` 查看
- *生信工具不可见？* 未配置 `BIO_DATA_ROOTS` 白名单，联系管理员
- *skill 改进卡该批吗？* patch 预览与建议一致即可批；写回前自动备份 .bak，可随时还原
