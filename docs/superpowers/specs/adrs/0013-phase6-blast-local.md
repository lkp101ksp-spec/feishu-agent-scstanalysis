# ADR-013: 本地 BLAST+ vs 仅 web API

| 字段 | 值 |
|---|---|
| 状态 | 已批准（2026-08-09）|
| 决策者 | 用户 + Claude |
| 影响 Phase | Phase 6 |
| 相关 spec | §6 本地 BLAST+ |

---

## 背景

Phase 4 MVP BLAST 仅 NCBI web API（受 3 req/s 限流）。Phase 6 增加本地 BLAST+ 二进制支持，实现离线科研。

---

## 选项

### A. 仅 web API（继承 Phase 4，已选 ❌）

依赖 NCBI web API。

- **优点**：无本地部署；用户门槛低
- **缺点**：受网络 + 限流；离线不可用

### B. 本地 BLAST+ 二进制 + web 兜底（已选 ✅）

用户安装本地 blast+ + 数据库；mode='auto' 自动切换。

- **优点**：离线可用；速度快；不受限流
- **缺点**：用户需安装 + 下载数据库（门槛高）

### C. 仅本地 BLAST+

强制本地。

- **优点**：离线强制
- **缺点**：未安装本地 blast+ 的用户无法使用

---

## 选择：**方案 B（本地 + web 兜底）**

---

## 后果

### 正面

- 已安装本地 blast+ 的用户享受离线 + 高速
- 未安装的用户仍可走 web API
- mode='auto' 自动决策；无需用户手动切换

### 负面

- 用户首次安装本地 blast+ 门槛高
- 本地数据库占用磁盘（>10 GB）

### 中性

- 复用 Phase 4 BlastNCBITool.handle() 路径；新增 _local_blast 分支

---

## 回滚条件

1. 本地 BLAST 与 web 结果不一致（≥ 10% 用户反馈）
2. 本地二进制注入风险被利用（≥ 1 起严重安全事件）

回滚方案：禁用本地路径（mode='web'）；web 仍可用。
