# ADR-014: 工具热加载 vs 仅 restart

| 字段 | 值 |
|---|---|
| 状态 | 已批准（2026-08-09）|
| 决策者 | 用户 + Claude |
| 影响 Phase | Phase 6 |
| 相关 spec | §7 工具热加载 |

---

## 背景

Phase 6 引入工具热加载：管理员上传 .py 实现 → AST check → ToolRegistry 注入，避免重启服务。

---

## 选项

### A. 仅 restart 后生效（已选 ❌）

新工具需重启服务才生效。

- **优点**：实现最简
- **缺点**：运维不便；高频更新场景不能接受

### B. 热加载：管理员上传 + AST P0 拦截（已选 ✅）

运行时注入新工具；无需重启。

- **优点**：运维友好；管理员可动态扩展能力
- **缺点**：AST 拦截必须严格；恶意代码风险

### C. 在线动态重载（无 restart）

新工具立即生效且旧工具替换。

- **优点**：更灵活
- **缺点**：实现复杂；旧工具的 in-flight 调用可能崩；Phase 7 推迟

---

## 选择：**方案 B（热加载 + restart 后生效）**

---

## 后果

### 正面

- 管理员可动态扩展工具能力
- 重启后工具持续生效（持久化）
- AST P0 拦截复用 Phase 3 已有机制

### 负面

- 旧工具替换不支持（需 restart）
- 100KB code 上限；复杂工具需重新设计

### 中性

- HotLoader 仅依赖 importlib；不需额外进程管理

---

## 回滚条件

1. 热加载被恶意利用（≥ 1 起严重安全事件）
2. AST 拦截绕过被披露（≥ 1 起）

回滚方案：禁用 `/admin/tools/upload` 路由；回到 restart-only 模式。
