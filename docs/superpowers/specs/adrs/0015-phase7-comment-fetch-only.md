# ADR-015: 协作评论仅 fetch + render（不持久化）

| 字段 | 值 |
|---|---|
| 状态 | 已批准（2026-08-09）|
| 决策者 | 用户 + Claude |
| 影响 Phase | Phase 7 |
| 相关 spec | §3 协作评论 |

---

## 背景

Phase 7 集成飞书 doc comment API。需要决定 Agent 是否持久化评论到本地 DB。

---

## 选项

### A. 仅 fetch + render（已选 ✅）

Agent 仅调用飞书 API 拉取评论，渲染到 IM。不持久化到本地表。

- **优点**：避免双系统数据一致性；评论源 = 飞书
- **缺点**：Agent 不能评论 / 回复

### B. Agent 持久化评论表

写本地表 + 飞书双向同步。

- **优点**：可分析与历史
- **缺点**：双系统一致性难维护；额外存储

### C. 仅展示（不响应）

不读不写；用户只能在飞书 doc 看评论。

- **优点**：实现最简
- **缺点**：用户消息中无法提及评论

---

## 选择：**方案 A（仅 fetch + render）**

---

## 后果

### 正面

- 避免双系统数据冲突
- 评论源 = 飞书 doc（用户编辑即可见）
- IM 指令 `/comments` 让用户在 chat 中查看

### 负面

- Agent 不能回复评论（不写）
- 评论历史无法本地分析

### 中性

- 评论触发 agent 行为推到 Phase 8

---

## 回滚条件

1. 用户反馈"agent 应回复评论"（≥ 20%）
2. 飞书 doc comment API 变更不可用（持续 ≥ 1 周）

回滚方案：Phase 8 增加本地评论表 + 双向同步。
