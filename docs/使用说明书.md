# 飞书科研 Agent 使用说明书

> 版本：2026-09-04 · 配套阅读：《平台功能说明书》（讲"有什么"），本文讲"怎么用"
> 适用对象：通过飞书使用本机器人的成员（无需任何技术背景）

---

## 0. 准备工作

| 事项 | 说明 |
|---|---|
| 找到机器人 | 在飞书搜索机器人名称，发起单聊；或拉入项目群 |
| 单聊 vs 群聊 | 单聊：所有功能可用，闲聊也会回复。群聊：**只响应 `/` 指令和 `#写到`**，其余消息静默（避免打扰） |
| 数据文件 | 生信分析需文件位于管理员配置的数据目录内（白名单外的路径会被拒绝并提示） |
| 无需安装 | 所有能力在服务端执行，手机/网页飞书均可 |

---

## 1. 五分钟上手

**第一步：打招呼**（单聊直接发消息）

```
你好，你能做什么？
```

**第二步：绑定一篇飞书文档当笔记本**

```
/bind-doc https://xxx.feishu.cn/docx/AbCdEfGh123
```

回复 `[成功] 已绑定文档 xxx，授权有效期至 …`。之后你的每次问答回复都会自动追加进这篇文档，30 分钟内有效，快过期时会自动弹「续期」按钮，点一下即可。

**第三步：试一个编码任务**

```
/code 在工作区创建 notes.txt，写入今天日期
```

会看到受理提示 → `[进行中] step 1 · ✓write_file` → 完成总结。

## 2. 场景教程

### 场景 A：问答 + 笔记沉淀（最常用）

```
（绑定文档后）
单细胞RNA-seq中UMI去重和counts有什么区别？        ← 直接发问
#写到 方法记录 | 我们选定 10x 平台，DMSO 处理 48h  ← 定点写入指定章节
```

- 每条回复先到 IM、再进文档，实现「边聊边沉淀」
- `#写到` 只写指定章节这一次，不影响默认追加位置

### 场景 B：多步研究任务

```
/research 读取绑定文档的实验设计，总结样本分组，并给出统计检验方案建议
```

流程：受理即回 → 后台规划执行（可能多步）→ 完成后发摘要 + 「同意写入/跳过」卡片 → 点「同意写入」落进绑定文档。任务较慢时可继续聊天，互不干扰。

**任务描述技巧**：越具体越好。差的：`帮我分析数据`；好的：`读取绑定文档第 2 节的样本表，按 batch 分组比较细胞数分布`。

### 场景 C：让 Agent 写代码干活（/code）

```
/code 把工作区 data.csv 按批次拆分成多个文件，并统计每批均值，结果存 summary.csv
```

你会依次看到：

1. 受理提示
2. 进度行：`[进行中] step 2 · ✓list_dir ✓read_file`
3. **审批卡**（若 agent 要跑白名单外命令，如 pip 安装）：点「批准」继续 / 「拒绝」中止
4. 完成总结：`[coding 完成] 步数 6 · 工具 4✓/0✗ · ~800 tokens` + 做了什么/产物路径

**工作区须知：**

- 每个聊天一个独立工作区，文件跨任务保留
- ` /code 列出工作区文件` 随时查看现状；`/code clear` 清空重来
- Agent 失败时会自动总结原因，不会无限重试（连续 3 步失败即停手）

### 场景 D：单细胞分析全流程

数据文件需在数据白名单目录内（例：`I:\bio_data\sample1`）。描述任务即可，agent 自己编排工具链：

```
（单聊或 /research 或 /code 均可触发生信工具）

对 I:\bio_data\sample1 做 10x 单细胞分析：先读入看下数据质量，
然后质控（线粒体比例上限 15%），标准流程处理，最后给我每群的标记基因
```

预期产物（自动发到 IM 并可入文档）：

| 步骤 | 你会收到 |
|---|---|
| 读入 sc_load | 细胞数/基因数/中线粒体比例概要 |
| 质控 sc_qc | 过滤前后统计 + filtered.h5ad |
| 处理 sc_process | processed.h5ad + **UMAP 聚类图** |
| 标记基因 sc_markers | 每簇 top 基因 + **dotplot 图** |

想补画图时继续说：`把 MS4A1、CD3D、NKG7 画小提琴图`（≤6 基因/次）。

### 场景 E：空间转录组分析

```
对 I:\st_data\spaceranger_out 做空间转录组分析：读入 → 质控 →
空间域聚类 → 每个域的标记基因 → 再做配体受体通讯分析
```

同样描述式触发（st_load → st_qc → st_process → st_markers → st_commot），收到空间域图、dotplot、通讯方向图等。

### 场景 F：处理 skill 改进审批卡

当某次 `/code` 因 skill 工具反复失败而中止后，会收到「skill 改进审批卡」，内容含：

```
- skill：qc_stat
- 问题：…（逐字引用了真实报错）
- 建议：…
- 目标文件：SKILL.md / tools.yaml
- patch 预览：…
```

**决策建议：**

- 报错引用与建议合理 → 点「批准写回」，原文件自动备份 `.bak`，下次调用生效（skill 越用越准）
- 拿不准 → 点「忽略」，无任何副作用
- 反悔了 → 到 `skills/<name>/` 下用 `.bak` 覆盖回来即可

---

## 3. 审批卡处理原则（通用）

所有审批卡（代码命令 / 文档写入 / skill 改进）规则一致：

- **只有任务发起者本人能点**，群里别人点了会提示无效
- 10 分钟不点按拒绝处理
- 重复点击安全（幂等，只按第一次算）
- 拿不准就拒绝/忽略——拒绝后可让 agent 换方案，忽略则什么都不发生

## 4. 疑难排查

| 症状 | 原因与处理 |
|---|---|
| 群里发消息没反应 | 群聊只响应 `/` 指令，改用指令或转单聊 |
| 绑定文档报 "document not found" | doc_id/链接抄错，重新复制完整链接 |
| 回复提示「文档绑定已过期」 | 发 `/bind-doc-renew`（30 分钟内还没过）或重新 `/bind-doc` |
| `/code` 说文件不存在 | 工作区是每个聊天独立的，先 `/code 列出工作区文件` 确认；跨聊天不共享 |
| 生信工具提示路径不在白名单 | 联系管理员把数据目录加进 `BIO_DATA_ROOTS` |
| 同一数据重复分析很慢 | 不会的——同路径同大小数据自动复用上次中间产物（dataset_ref 幂等） |
| 审批卡点了像没反应 | 首次点击已生效（重复点击幂等）；确认是你本人发起的任务 |
| 分析图没收到 | 大图上传偶有延迟；也可在绑定文档里找 ImageBlock |

## 5. 最佳实践

1. **任务描述三要素**：对象（哪个文件/文档哪节）+ 动作（做什么）+ 期望产物（给我图/表/结论）
2. **长任务先绑文档**：`/research` 和生信分析的结果落文档比翻聊天记录好找
3. **`/code` 工作区当项目目录用**：跨任务保留，适合迭代式干活（今天处理、明天接着画图）
4. **审批卡只批看得懂的**：patch 预览/命令内容看不懂就忽略，不会有损失
5. **skill 改进卡尽量批**：这是系统自我进化的一环，批准后下次同类失败会减少；有 .bak 兜底，风险可控
